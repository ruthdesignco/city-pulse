## Focus question answers

**1. Security process fix.** Both incidents share one cause: a human and an agent copying a secret value by hand through a CLI that can reach every project in the account and picks its target implicitly. The board agrees on:
- Log the agent's CLI out.
- Tyler runs every secret, deploy and `db push` command himself, with an explicit `--project-ref`, from a committed script.
- Secret values never appear in terminal output or screenshots.

The board splits on whether to go further and remove the human from the loop entirely: see Disagreements.

**2. Correctness and resilience.**
- Budget gating: correct. The fixed window is safe because 75 s spacing alone caps any rolling hour at 48 calls.
- Dead feed that returns errors: correct. Buses freeze and dim, the pill shows "stale" with "feed errors".
- Frozen feed that keeps returning 200: wrong after 2 h (fix 5).
- Timestamp assumption: true today (verified: about 137 vehicles share each feed timestamp) but not enforced (Blocker 3).
- Clock skew: a header ahead of the database clock reads "live · 0 s ago" indefinitely (fix 5).

**3. Code quality and test coverage.** The TypeScript is strong: 180 tests, and the poller handler covers every gating, auth and redaction path. The gap is entirely in the SQL, which an agent will rewrite in Weekend 2 when police data joins `current_state`. There is also no CI.

**4. Demo readiness.** Osmani's ranking, which nobody disputed:
1. **Trails.** You already have two observations about 75 s apart. Draw the route-shape segment between them as an additive line that fades out. At 2.7 m/s that's about 200 m, or about 55 px even at today's zoom. It's honest data, and it makes bunching and gaps visible, which is the story SPEC promises ("light trails").
2. **Open closer.** Start at about 1,500 m, about 50° down: a bus is about 25 px and moves about 2.2 px/s. Keep the 4.5 km view as where the idle drift pulls out to.
3. **A minimum on-screen size plus bloom.** Scale instances with distance so a bus never drops below about 4 px wide. Add bloom, which is already installed but unused, at a threshold of about 0.8 so only the `toneMapped:false` vehicles glow.
4. **Stale buses shouldn't disappear.** `muniStale #5a5f86` is darker than `streetMajor #7a83b8`, so a stale bus looks like a missing bus. This touches a settled decision ("fade to a muted tone"); see Decisions.

Never speed up live data. Any replay at N× must be labeled on screen.

## Disagreements
1. **How far the secret fix goes.** Hunt vs Hightower; Willison leans toward Hunt.
   - Hunt: make Vault the single source. Generate the secret in SQL (`gen_random_bytes`) so no human ever sees it. The function reads it through a service-role-only RPC and caches it about 5 min. Process fixes alone cure incident 1 but not incident 2, because every rotation is another paste or screenshot.
   - Hightower: that's new code (an RPC, a cache, a cold-start dependency, up to 5 min of 401s per rotation) to fix a process failure. For a secret rotated once, a runbook is enough.
2. **Where the SQL test runs.** Kleppmann and Osmani vs Hightower.
   - Kleppmann and Osmani: in CI, about 10 extra lines with a Postgres service container. The change most likely to break the view is an agent's `create or replace` in Weekend 2, and nobody runs a check kept off to the side.
   - Hightower: commit the check and run it by hand until the schema changes more than once a weekend.
3. **Sentry now?** Majors vs Quinn and Hightower.
   - Majors: yes, so a blank page reaches Tyler.
   - Quinn: a third vendor whose free quota a WebGL failure loop could use up mid-spike. Start with the boundary, Healthchecks and Vercel logs, and sample and cap Sentry if it comes later.
   - Hightower: once the boundary is in, Sentry can wait.
4. **Order of operations.** Majors (and Hightower, after cross-examination) want the dead-man's switch before rotation, so rotation is verified by a ping. Hunt says rotate first, because the leak is live and checking `ingest_runs` is enough verification for tonight. Chair: rotate first.
5. **What the spend cap is for.**
   - Quinn: the cap turns a surprise bill into a throttled demo, the right failure for a portfolio piece.
   - Majors: it turns it into an outage nobody notices unless the dead-man's switch and a coarse 401 counter exist.
   - Both can be done.
6. **Deny rules.** Hunt lists them as a fix. Willison says they're typo guards, not a boundary. Logging the CLI out is what matters.

## Strongest dissent
Hunt: the board's process fixes cure the wrong-project failure, but not the one that already leaked a secret.
- As long as the poller secret exists as a value a human generates and types into two places, every rotation is another chance for a screenshot, paste or scrollback leak, and another chance for a silent half-rotation.
- Generating it inside Postgres and reading it from Vault means there's nothing to leak and nothing to get out of sync.
- He accepts the costs: one RPC per cold start, and up to 5 min of fail-closed 401s on rotation, which burn no budget. The function must check its cached secret before any DB call, so bot traffic doesn't drive database load.

What would change his mind: Tyler committing that the secret will be rotated rarely and only through the scripted runbook in his own terminal, with no screen sharing or screenshots. Then the residual risk is small enough to leave alone.
